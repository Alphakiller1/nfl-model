# NFL model baseline, 2017–2025

> This remains the coefficient-selection and parameter-sweep record. Its
> leave-one-season-out protocol excludes each season from its own fit but can
> use later seasons when scoring an earlier one. The stricter historical
> simulation in `reports/regime_audit_2026.json` trains only on prior seasons
> and supersedes this document for headline performance claims.

Everything in `matrix.py`, `totals.py`, and the constants at the top of
`ratings.py` and `preseason.py` comes from here. Reproduce with:

```bash
python scripts/fit_matrix.py          # full fit + sweeps
```

## Sample and protocol

| | |
| --- | --- |
| Games scored | **2,383** completed regular-season games, 2017–2025 |
| History loaded | 2014–2025 (the priors need three completed seasons) |
| Feature timing | strictly point-in-time — a week-*W* game sees only games before *W* |
| Coefficients | **leave-one-season-out** — no game is scored by a model that saw it |
| Source | nflverse `games.csv` and `stats_team_week_<season>.csv`, no API key |

Leave-one-season-out is the only protocol whose MAE can be compared with the
market's, because the market never saw the answer either. An in-sample fit would
beat the closing line on this data and mean nothing.

## Headline result

**The model does not beat the closing market, on either the spread or the total.**

### Margin

| Estimator | MAE | vs market |
| --- | ---: | ---: |
| Power ratings only | 10.4298 | +0.5590 |
| Efficiency matchup model only | 10.4193 | +0.5485 |
| **Published (50/50 blend)** | **10.3134** | **+0.4427** |
| Closing spread | 9.8708 | — |

ATS on games where the model disagrees with the closing line:
**1158–1165–60 = 49.85%**, 95% CI **[47.82%, 51.88%]**, against a 52.38%
breakeven. The interval contains 50% and lies entirely below breakeven: this is
unproven and slightly negative, not a signal.

Calibration slope of actual margin on published margin: **1.035**. The model is
correctly *scaled*; it is simply less informed than the market.

### Total

| Estimator | MAE |
| --- | ---: |
| League mean (45.59) | 11.0423 |
| Raw model total | 10.8530 |
| **Shrunk model total (λ = 0.70)** | **10.8076** |
| Closing total | 10.4700 |

O/U on disagreements: **1160–1203–20 = 49.09%**, 95% CI [47.07%, 51.11%].

The raw total is over-dispersed — the slope of actual on predicted is near 0.63.
Shrinking 30% toward the league mean lifts it to **0.907** and buys 0.045 points.
Residual SD is 13.69 against an actual-total SD of 13.84, so the total model
explains very little of the variance and a projected scoreline should be read as
a centre of mass.

### By regime — and it is the opposite of college football

| | n | model | market | gap | dispersion |
| --- | ---: | ---: | ---: | ---: | ---: |
| Weeks 1–4 | 572 | 10.2436 | 9.8514 | **+0.3922** | 0.946 |
| Weeks 5–9 | 643 | 10.3806 | 10.0933 | +0.2873 | 0.872 |
| Weeks 10–18 | 1,168 | 10.3106 | 9.7577 | **+0.5529** | 0.770 |

cfb-model's preseason regime is its worst (1.8 points behind the market in weeks
1–4 against 0.37 later), which is why that repo refuses to publish an edge there.
The NFL is the reverse: the gap is *narrowest* in September and widest in
November, and model dispersion falls from 0.95 of the market's to 0.77 as the
season goes on.

The reading is availability. By week 10 the market is pricing injuries, snap
counts and roster news this repo does not model at all, and the model's
compressed dispersion is it hedging against information it cannot see. In week 1
there is less of that to know, so a prior-season model competes better. This does
**not** make week 1 tradeable — 49.85% ATS is a season-long figure and the
weeks 1–4 slice is not above breakeven either — but it does mean the preseason
board is the model's strongest relative statement, not its weakest.

## The specification, and the one that was thrown away

The model predicts points scored by **one** team in **one** game:

```
points(A vs B) = intercept + Σ gₓ · ( offₓ(A) + defₓ(B) ) + home_field
```

Margin, total, scoreline and both unit rankings all derive from this single fit.

### Why offence and defence share a coefficient

The first specification gave `off_x` and `def_x` free coefficients. It fitted
**`def_epa` positive** — allowing more EPA per play "improved" the home margin —
and `off_epa` near zero with the wrong sign. The cause is collinearity:

| pair | r |
| --- | ---: |
| `off_epa` / `off_first_down` | +0.901 |
| `def_epa` / `def_first_down` | +0.833 |
| `off_epa` / `off_explosive` | +0.649 |
| rating gap / `off_epa` | +0.758 |

Variance inflation on `off_epa` was 13.6. The collinear pair split the effect
with opposite signs, producing a model that predicted acceptably and *described*
football backwards — and nothing about the output shape reveals that. A
defensive ranking built on it would have looked entirely plausible while
rewarding defences for giving up yards.

`off_x` and `def_x` measure the same per-play quantity in the same units, so the
matchup is their sum. The symmetric form costs **0.016 points** of MAE (inside
the noise) and every coefficient it produces carries the sign football says it
should.

### Coefficients

Points contributed per unit of ( own offensive rate + opponent's defensive rate ).

| Family | Coefficient |
| --- | ---: |
| Intercept | +2.876 |
| EPA per play | +6.988 |
| First-down rate | +34.493 |
| Explosive-play rate | +54.625 |
| Sack rate | −21.454 |
| Turnover rate | −101.795 |
| Home field | +1.740 |

### Standardised weights

|coefficient| × the spread of that rate across teams, normalised within group.

| Offense | | Defense | |
| --- | ---: | --- | ---: |
| first down rate | 0.2968 | first down allowed | 0.2877 |
| epa per play | 0.1960 | takeaway rate | 0.2221 |
| explosive rate | 0.1886 | explosive allowed | 0.1917 |
| giveaway rate | 0.1820 | epa allowed | 0.1811 |
| sack rate allowed | 0.1366 | sack rate | 0.1174 |

The two groups share coefficients but not spreads, and the difference is the
finding: takeaways separate defences (0.222) more than giveaways separate
offences (0.182), while EPA separates offences more than defences.

### What was dropped

The inherited prior in `nfl-genesis/src/genesis/logic_matrix.py` asserted seven
offensive families — EPA 0.30, success rate 0.18, explosiveness 0.14, early-down
pass efficiency 0.14, pressure allowed 0.12, red zone 0.07, special teams 0.05.
Three of them (early-down pass efficiency, red-zone conversion, special-teams
field position) are not derivable from the weekly team box score. They were
dropped rather than shipped as decorative weights on a live board. True success
rate needs play-by-play; first-down rate stands in for it.

## Parameter sweeps

Each parameter was swept against out-of-sample MAE of the published margin, with
everything else held at the values below. **Two of the five came back flat, and
they are labelled as flat rather than presented as tuned.**

### Preseason blend K — the one that matters

`weight_on_live = games_played / (games_played + K)`

| K | MAE |
| ---: | ---: |
| 1 | 10.3537 |
| 4 | 10.3433 |
| **6** | **10.3338** |
| 8 | 10.3450 |
| 12 | 10.3815 |

Selected **6.0**: a team needs six games before this season outweighs last.

> The first version of this sweep reported *identical* MAE for all seven values.
> `live_weight` had `k` as a default argument, which binds once at import, so
> reassigning the module constant did nothing and the sweep measured the same
> model seven times. A perfectly flat curve across a parameter that obviously
> matters is a bug report, not a finding. `ratings.build` had the same defect and
> now resolves `cap`, `home_field` and `halflife` through a sentinel;
> `tests/test_ratings.py` pins both behaviours.

### Blowout cap — flat

| Cap | MAE |
| --- | ---: |
| none | 10.3199 |
| **42** | **10.3163** |
| 35 | 10.3167 |
| 28 | 10.3190 |

**7.0%** of NFL games are decided by 28+, against **36%** of FBS games — which is
why cfb-model buys half a point of MAE from capping and this repo buys 0.004.
The cap is kept at the argmin only to bound what one freak result can do to a
September rating. Copying college's 32 unexamined would have looked more
decisive and meant less.

### Home field — flat, and lower than the measured value

| Rating-path constant | MAE |
| --- | ---: |
| 0.8 | 10.3144 |
| **1.2** | **10.3127** |
| 1.62 | 10.3163 |
| 2.0 | 10.3217 |
| 2.4 | 10.3307 |
| 3.0 | 10.3526 |

Measured mean home margin: **+1.90** (2014–2019), **+2.06** (2021–2025). Home
field did *not* decline post-2020 in this sample.

The published rating-path constant is 1.20 anyway, and the gap is structural
rather than empirical: the published margin is a 50/50 blend with the efficiency
path, which carries its own fitted home-field term of **+1.74**. The blend
therefore applies **1.47** points in total. Setting this constant to the measured
2.06 would double-count with the other half of the blend.

## Opponent adjustment

Worth ~0.09 points of MAE — far less than cfb-model's 0.30, because NFL schedules
overlap much more than college ones. Kept because it is cheap and it adjusts the
right quantity: six of a team's games are inside its own division and a
first-place schedule is a real thing.

## Measured context

| | |
| --- | ---: |
| Margin SD (raw) | 14.32 |
| Margin residual SD (published forecast) | **13.32** |
| Total SD (raw) | 13.84 |
| Total residual SD | **13.69** |
| Mean total | 45.55 |

`win_probability` uses the **residual** SD (13.32), not the raw spread of NFL
margins (14.32). P(home wins) is P(actual > 0 | forecast), so the relevant
dispersion is the model's error; using 14.32 would claim more uncertainty than
the forecast has and push every probability toward 50%.

## What this evidence does and does not license

Three of twelve production gates in `nfl-genesis`
`registry/production_requirements.yaml` are satisfied. The authority is
`RESEARCH_ONLY`, `may_bet` is False, and `SPREAD_LAMBDA` is 0, so the published
margin is the closing line. The model's own number is shown beside it and the
difference is reported as a **gap**, never an edge — `forecast._points_edge` is
the single place that decision is made, and the ATS interval above is the reason
it returns `None`.
